# 陷阱记录

实战中真实踩到或险些踩到的坑。每条给出**错误做法 → 识别方法**。案例细节已去标识化。

## 1. 把「抓不动」当成「是假的」

`x.com` 页面 fetch failed，直觉会认为链接是伪造的。
**识别**：反爬与伪造是两件事。改用①时间戳反解 ②两个独立镜像 API ③读取附件图，三条一致才下结论。

## 2. 把搜索结果标题当成证据

搜索引擎会给出「某市 XX 公司 - 天眼查」这类标题，同一名称出现在多个城市，看起来像已证实存在多家关联公司。
**识别**：标题只证明**被索引**，不证明关联。必须拿到公司页正文；拿不到就写「仅为索引条目，未核实详情」。同名主体一律按统一社会信用代码区分。

## 3. 同名蹭名主体污染结论

目标主体获得公开曝光的前后数日内，出现了同名公司。
**识别**：把每个同名主体的**法人、注册资本、成立日期**列成表；与事件时间线对照。抢注时间紧贴事件时间＝蹭名，不是关联。反向风险同样存在：**别人的风险记录不能用来洗白或抹黑目标主体**。

## 4. 把「未查到」读成「干净」

工商风险字段（被执行、失信、行政处罚、经营异常）一个都没取到。
**识别**：取证受阻必须先说明原因（登录墙 / 反爬 / 接口失效），再明确写「未取到任何数据，不能视为无风险」。能实测的只有同名主体时，要标注「该数据属另一主体，不可外推」。

## 5. 把子调查的结论当成自己验证过的

三路并行子调查会返回看起来很硬的数据（哈希、字节数、粉丝数）。
**识别**：主代理必须亲自复核最吃重的 2–3 条。复核失败（接口风控、页面截断）时如实标注「子调查实测，我这边未能复现，方法可复现」。**这不是减分，是可信度的来源。**

## 6. 认错账号，热度差一个数量级

一度把核心成员的私人账号当成官方号。
**识别**：先确认账号归属——官方号通常有企业认证、命名与品牌一致。实测官方号粉丝只有百级，与私人号差一个数量级；用错会把「几乎没有声量」误读成「小有声量」。

## 7. 混淆 HTTPS 证书与代码签名

「证书不受信任」这个说法把两件事混成一件。
**识别**：网站证书正常（浏览器不报警）≠ 安装包已签名（Windows 会显示「未知发布者」+ SmartScreen）。分别取证、分别表述。

## 8. 用截断文件判断数字签名

只取安装包前 4MB 时，PE 证书表看起来存在。
**识别**：签名校验必须用**完整文件**。用完整文件才得到 `NotSigned` 的正确结论。

## 9. 把措辞升级直接判成「诈骗」

招聘图写「获得了某机构投资」，而公司官网只写「孵化」。
**识别**：正确做法是把各渠道用词并排成表，定性为**单方面措辞升级**。机构确有资助机制时，该说法可能为真但未经公司确认——结论应是「未证实 + 口径升级」，而不是「造假」。

## 10. 名词撞车导致误判

主体名称与某已知骗局关键词重合，而该词同时是行业内的官方译名。
**识别**：看到高危关键词先做**主体同一性判定**（业务形态、主体登记、公开痕迹、风险记录四维度比对），再决定是否关联。不要因为关键词命中就给公司贴标签。

## 11. 人数类宣称不做算术

「60% 的成员是前 X 工程师」，而团队只有 3 人。
**识别**：60% × 3 = 1.8，无整数解。可独立佐证的只有 1 人。**比例类宣称在小基数下无意义**，要换算成人头再核对。

## 12. 首页超时被当成「网站有问题」

官网首页多次 30s 超时，一度准备写「网站不稳定」。
**识别**：先换入口（sitemap / 子页 / robots）验证站点是否可用；同时如实说明**无法区分是对方网络问题还是本方网络问题**，不把它写成对方的缺陷。

## 13. 事件时间线掩盖了主体年龄

拿过奖项、有媒体报道、开过发布会，会让主体显得「有历史」。
**识别**：把「获奖日」「注册日」「域名注册日」「产品首版发布日」排成时间线。实测：公开获奖早于主体注册，报告当天该主体成立不足两个月。**这类反差是最有价值的发现。**

## 14. 把「有产品」等同于「能交付」

有官网、有 Demo、论坛里有实物出板照片。
**识别**：拆成三层——①能下载/能演示 ②有价格与购买入口 ③有发货/交付记录。三者常只有第一层成立。硬件尤其要看价格、预售、众筹、渠道上架。

## 15. 报告按发现顺序而不是按影响排序

容易把「有没有某机构投资」写在最前面，而把「签约甲方是哪家公司」埋在末尾。
**识别**：风险清单按**对读者的实际影响**排序。对求职者：签约主体 > 社保与意外险 > 书面 offer 条款 > 机构背书口径 > 备案与商标。
